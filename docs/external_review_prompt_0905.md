## 프롬프트 (그대로 붙여넣기)

```
당신은 추천 시스템 점수 설계를 검토하는 리뷰어다. 아래는 1인 개발 인디게임 추천 서비스 "Hidden Gem" 의
점수 로직 v7 과 그 결정 기록이다. 어제 다른 검토자 3명이 요약 문서만 보고 검토했다가 코드에 있는
가장 큰 결함(장르 핵심 지표의 목표값이 상수 5.0 — score_v6.py:184-188)을 전원 놓쳤다.
그래서 이번엔 소스를 준다. 요약을 믿지 말고 코드를 읽어라.

### 바꾸지 않는 전제 (여기 반대하는 제안은 필요 없다)
1. 점수는 사용자의 취향 입력(지표:값 3~5개) 또는 검색 문장에 따라 달라진다. 같은 게임이 질의마다 다른 점수를 받는 것은 의도다.
2. 데이터는 지우지 않는다. 노출만 is_active 로 조절한다.
3. 학생 모델(gpt-5.4-mini) 데이터는 교사(GPT-5.4)와 품질 차이가 없어야 한다. 품질을 낮추는 절감은 하지 않는다.
4. 서비스 취지는 "리뷰 적고 평가 좋은 게임 발굴". 스팀 인기순위와 달라야 한다.

### 검토 범위 — 다섯 가지를 각각 답하라

A. **v7 공식 자체 (score_v7.py)**
   P = 사용자 지정 지표 전부(임계 없음) / w = 1 + |pref−5|/5 / dist = sqrt(Σw·diff²/Σw) /
   match = exp(−(dist/3.5)²) / core = match×93 / final = core + gem(≤6)
   - 이 공식이 전제 1·4 를 v6 보다 잘 구현하는가? 못 하는 경우를 **구체적 입력값으로** 제시하라.
   - τ=3.5 의 결과: 두 지표 중 하나가 8점 어긋나면 Core 93 → 6.8 이다. 이게 맞나, 과한가? 대안 τ 와 그 근거.
   - w = 1+|pref−5|/5 (1.0~2.0). 다른 가중 방식이 낫다면 무엇이고 왜.
   - 사용자가 지표 1개만 주면 거리가 1차원이다. 동점·저변별을 어떻게 볼 것인가. 우리는 임베딩 타이브레이커를
     넣지 않기로 했다(프리셋에 텍스트가 없다). 이 결정을 공격하라.
   - 장르 핵심 지표를 점수에서 완전히 뺐다. "장르 정체성"이 점수에 있어야 하는 경우가 있나? 있다면 D-26 을
     다시 만들지 않는 형태로 어떻게 넣나.
   - X-Factor(18점, 8+ 지표 가산)를 제거했다. 대체 없이 제거하는 것의 부작용은? "독창성" 신호가 필요하다면
     질의와 무관하지 않은 형태로 어떻게 정의하나.

B. **결정 기록 (decisions_0905.md) R-1 ~ R-7**
   각 결정에 대해 (a) 동의 (b) 조건부 동의 + 조건 (c) 반대 + 대안 중 하나로 답하라. 특히:
   - R-3 gem 증거 지수: Wilson 하한(z 1.96) × 로그 무명도(cap 20000, exp 0.5, floor 50). 리뷰 50개 100% 가
     리뷰 1000개 95% 보다 높은 점수를 받는다. 취지 4 에 맞는가? 파라미터 대안.
   - R-4 노출: 리뷰 ≥3 AND Wilson ≥0.35. 너무 느슨한가 빡빡한가. 신작 63% 가 리뷰 9개 이하인 분포에서.
   - R-2 세 경로(취향/유사게임/문장검색)의 표시 척도를 통일하지 않기로 했다. 반대하면 통일 방법을.
   - R-6 순서: 폴백 수정 → 절제 측정 → v7 전환 → gem 전환 → 노출 → 백필 재개. 순서가 틀렸다면 어디가.

C. **생애주기 분리와 신작 리그 (decisions R-11/R-12, lifecycle.py, routers/ranking.py, 06 명세)**
   개발자 취지: "신작으로 신생 게임을 보호해서 그들만의 리그를 만들고 보여주자."
   - new(출시 ≤180일, 리뷰 수 무관) / established / famous(리뷰 ≥2만). 나이를 먼저 본다 — 카나리아: 리뷰 8.7만짜리 신작
     MECCHA CHAMELEON 이 신작 랭킹 1위여야 한다. 이 경계와 순서를 공격하라.
   - 메인 추천 기본 제외는 "리뷰 < 100 인 신작"만. 100 이 맞나? 다른 기준(Wilson? 출시 후 일수?)이 낫나?
   - 랭킹 4종 정렬 정의: steady=Wilson×무명도 / rising=30일 상대 증가율 Δ/max(이전,50) / new=리뷰/일(7일 하한) /
     new_quiet=리뷰<100 중 Wilson 순. 각각 "이 정렬이 그 탭의 질문에 답하는가"를 따져라. 조작 가능성(리뷰 어뷰징)도.
   - 신작 리그(new_only): 신작끼리만 취향 매칭. 취향 축 3~4개로 신작 3천 개를 매칭하면 동점이 많다 — 그 다음 정렬은?
   - 지금 시점의 사실: 수집이 3/16 이후라 학생 코호트 거의 전부가 '신작'. 정착 코호트는 교사(인기작)만.
     이 상태에서 스테디 탭이 사실상 "교사 4,141개 안의 발굴 지수 순"이 된다. 문제인가? 어떻게 다뤄야 하나?

D. **우리의 예측이 틀린 기록 (05 §5, 31)** — 학생 스케일 보정을 걸고 "힐링·서사 교사비율 하락, 액션 유지"를 예측했다.
   결과: 힐링만 하락, 서사 불변, 공포 악화(0.85→1.00). 원인 분석(절편이 0 목표를 밀었다 / 편향은 바닥 효과)이 맞는지,
   다른 설명이 있는지 따져라. 이 실패에서 우리가 못 배운 것이 있으면 말하라.

E. **우리가 또 놓친 것**
   어제 놓친 D-26 은 "함수의 기본값 인자가 호출 맥락에서 채점 규칙이 된" 사례였다.
   같은 부류 — 호출자와 피호출자의 계약 불일치, 조용한 폴백, 이름과 동작이 다른 것 — 를 소스에서 찾아라.
   recommender.py 의 recommend_by_preference → score_v7 호출 경로, resolve_null 정책, 동점 정렬 키,
   캐시 키 구성을 특히 봐라. **문서에 이미 적힌 것(D-1~D-26)을 다시 말하지 마라.**

### 답변 형식
- 모든 지적에 file:line 을 단다. 라인을 못 대면 "추정"이라고 쓴다.
- 심각도: 치명(의도 위반) / 높음(순위 왜곡) / 중간 / 낮음.
- 대안은 **구체적 공식 또는 값**으로. "재검토 필요" 같은 말은 답이 아니다.
- 확신이 없는 것은 "가설: ..., 검증 방법: ..." 형태로 쓴다.
- 우리 결정에 동의하는 항목은 한 줄로 끝내라. 반대하는 항목에 분량을 쓰라.
- 마지막에 "이 검토에서 가장 중요한 지적 하나"를 고르고 이유를 써라.
```

## 질문할 때 지킬 것 (개발자용 메모)

1. **소스를 준다. 요약을 주지 않는다.** 검토자가 요약을 읽으면 요약의 맹점을 물려받는다. 어제 셋이 그랬다.
2. **전제를 못 박는다.** 안 그러면 "질의마다 점수가 다르면 안 된다" 같은 전제 부정에 분량을 쓴다.
3. **동의는 짧게, 반대는 길게** 라고 명시한다. 안 그러면 칭찬 60% 가 온다.
4. **구체적 입력값·공식·라인을 요구한다.** "재검토 필요", "고려해야", "균형" 은 답이 아니다.
5. **이미 아는 것을 반복하지 말라고 한다.** D-1~D-26 목록을 주고 "이건 다시 말하지 마라"고 해야 새 것이 나온다.
6. **두 모델에 같은 걸 물었을 때 일치하면 근거가 아니다.** 같은 입력 = 같은 맹점. 서로 다른 것만 봐라.
   반대로 **불일치하는 지점**이 가장 값진 정보다 — 거기가 판단이 갈리는 곳이다.
7. **실측을 함께 준다.** `--diff s1 s2` 와 `scripts.ablation` 출력이 있으면 넣어라. 없으면 "실측 없음"이라고
   쓴다. 검토자가 숫자를 지어내지 않게.
8. 받은 답은 **코드로 확인한 뒤** 기록한다. 검토자 말이 근거가 아니다 — 어제 R3 도 우리도
   "gem_bonus 키" 건에서 응답을 확인하지 않아 틀렸다.
9. 답이 오면 `external_review_log` 에 **출처(모델·도구)·지적·판정·근거** 4열로 붙인다. 판정 없는 기록은 안 한다.
