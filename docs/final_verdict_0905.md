## 2. 새로 발견한 것 — Core 의 목표값이 상수 5.0 이다 (D-26)

`score_v6.compute_core_score` (`score_v6.py:184-188`):

```python
for f in all_core_fields:                       # 장르 핵심 2~5개 + 의도 지표(v>=7)
    target_vec.append(target_metrics.get(f, 5.0))   # ← 장르 핵심은 preferences 에 없다 → 5.0
    game_vec.append(game_metrics.get(f, 5.0))
    weights.append(2.0 if f in intent_fields else 1.0)
```

`recommend_by_preference` 는 `target_metrics=preferences` (`recommender.py:894`) 로 **사용자가
입력한 키만** 넘긴다. 따라서 장르 핵심 지표의 목표값은 전부 **5.0** 이다. Core 는
"사용자가 원한 것에 가깝나"가 아니라 **"이 게임이 자기 장르 핵심에서 얼마나 평범한가"**를 잰다.

### 공식 그대로 계산한 결과 (힐링 프리셋 `{cozy 9, time_pressure 1, reflex 2, melancholy 3}`)

의도 지표는 `v >= 7` 인 `cozy_factor` 하나만 살아남는다. 나머지 셋은 **버려진다**.
캐주얼 장르 → `DEFAULT_CORE_METRICS` 5개(narrative, replay, art_style, audio, exploration), 목표 5.0.

| 게임 프로필 | Core |
|---|---|
| 장르 핵심 전부 **5**, cozy **9** | **66.1** (도달 가능 최대) |
| 장르 핵심 전부 **8**, cozy **9** | 54.8 |
| 장르 핵심 전부 **9**, cozy **9** | **50.0** |
| 장르 핵심 전부 5, cozy **6** | **56.3** |
| 장르 핵심 전부 5, cozy 3 | 41.6 |

- **뛰어난 게임(핵심 9)이 평범한 게임(핵심 5)보다 16.1점 낮다.** Gem 예산(6) 전체의 2.7배.
- **cozy 6 짜리 평범한 게임(56.3)이 cozy 9 짜리 뛰어난 게임(50.0)을 이긴다.**
  사용자가 말한 지표 하나가, 말하지 않은 지표 다섯 개의 "평범함 보상"에 진다.
- 인디 장르의 핵심은 `art_style_uniqueness`·`narrative_depth`·`audio_design` 이다.
  → **독창적 아트(9)가 페널티**다. 히든 인디 젬 사이트에서.
- X-Factor 는 장르 핵심을 **제외**하고 계산한다(`:232-237`) → 장르 핵심에서 뛰어난 게임은
  Core 에서 깎이고 X-Factor 에서도 받지 못한다. **이중 페널티.**

s0 힐링 상위 10 에 `Celebrity Memory - 12in12`(gem 1), `Minimalist Circuit`(gem 8),
`10 Beautiful Postcards`(gem 4) 가 Core 63~64 로 들어와 있는 것이 이 공식의 결과다 —
cozy 만 높고 나머지는 평범한 프로필이 최적해다.

### 왜 이렇게 됐나
`score_v6` 는 `target_metrics` 가 **49개 전체가 채워진 dict**(기준 게임의 지표 같은 것)라는
전제로 짜였다. `by-preference` 는 4개짜리 sparse dict 를 넣는다. 호출자와 피호출자의 계약이
어긋난 채로 `.get(f, 5.0)` 이 조용히 메워버렸다. **`system_invariants.md` §4 A분류
("연결 지점을 이름으로 추측") 의 가장 큰 사례**이고, 세 검토자가 못 본 이유는 as-is 문서
§3 다이어그램이 `diff = (target - game) x weight` 라고만 적고 target 의 출처를 안 그렸기 때문이다.

### D-8 의 일반화
`v >= 7` 은 "부정 선호(0)" 만 버리는 게 아니다. **7 미만 전부**를 버린다.
힐링 프리셋 4개 중 3개, 공포 프리셋 `{horror 9, melancholy 6, cozy 0}` 3개 중 2개가 점수에
들어가지 않는다. 0~10 스케일의 **아래 절반이 죽어 있다.** "낮은 시간 압박"은 힐링의 본질인데
표현할 방법이 없다.

### 정정할 것
**(a) rec_snapshot 의 경로 B/C gem 키 수정은 효과가 없다.** R3 도 나(Opus)도 틀렸다.
`format_recommendations_by_game`(`recommender.py:1140-1163`)와 `format_semantic_results`(`:1212-1232`)
는 `score_breakdown` 을 **응답에 넣지 않는다.** s0 스냅샷의 bygame·semantic 시나리오는 전부
`score_breakdown: {}` 다. 내부 dict 의 키 이름을 맞춘 것은 무해하지만, **경로 B/C 의 gem 기여분은
현재 API 로 관측 불가**다. 고치려면 포맷터 두 곳에 `score_breakdown=r.get("score_breakdown", {})`
한 줄씩 추가해야 한다(추가만 하는 안전한 변경).

**(b) "X-Factor 는 선택 게이트" 가설 — 증거가 반대쪽으로 기울었다.**
홀드아웃 150건(교사 인기작)에서 X-Factor 근사치를 계산하면 **교사 라벨 100% / 학생 라벨 100% 가
18점 포화**, 15.6 미만은 **0건**. 상위 10 안에서도 15.6~18. 즉 인기작 풀에서는 상수이고,
게이트 역할이 있다면 전체 풀의 **희소 꼬리(8+ 지표가 적은 게임)에서만** 작동한다.
어느 쪽이든 결론은 같다: **X-Factor 는 질의 정보를 전혀 담지 않으며(D-6), 신뢰 불가 지표에
가장 많이 반응한다.** 홀드아웃에서 학생이 교사보다 8+ 를 더 자주 찍은 지표 1위가
`monetization_fairness`(교사만 13 / 학생만 42, r=0.36) 다. X-Factor 의 입력 중 가장 시끄러운
지표가 가장 자주 발화한다.
→ 문서의 "강한 가설" 표기는 **"전체 풀 측정 전까지 미결"**로 한 단계 더 내린다.
"X-Factor ↔ 인기도" 보류 판정은 유지. 코호트 편향(학생이 덜 받는다)은 **아니다** — 학생이 더 받는다.

**(c) 검토의 일치는 근거가 아니다** — 이 판정은 그대로 유지하되, 이번에 실증됐다.
세 검토자 + Opus 문서가 D-26 을 전부 놓쳤다. 입력이 같으면 맹점도 같다.
**다음 외부 검토에는 as-is 문서가 아니라 `score_v6.py`·`recommender.py` 원문을 넘겨야 한다.**

## 4. 학생 데이터 품질 — "교사급" 에 붙일 단서

MAE 0.77 은 평균이다. 홀드아웃 150건에서 **상관 r < 0.7 인 지표가 11개**다:
`monetization_fairness` .36 / `modding_support` .43 / `tutorial_quality` .48 / `save_flexibility` .51 /
`ui_ux_polish` .55 / `progression_clarity` .59 / `community_dependency` .61 / `art_style_uniqueness` .63 /
`animation_quality` .67 / `audio_design` .68 / `difficulty_accessibility` .70.

- 대부분 σ 가 작은 지표라 MAE 는 낮다. **취향 매칭(거리)** 용도로는 문제 없다.
- 그러나 **임계값 기반 사용(X-Factor 의 `>= 8`, 뱃지·필터)** 에는 r 이 중요하다.
  8+ 판정 일치: 교사 발화 865건 중 학생 일치 686(79%), 학생 단독 발화 237건.
- **인디 장르 핵심 3개 중 2개(`art_style_uniqueness`, `audio_design`)가 이 목록에 있다.**
  D-26 을 고쳐 장르 핵심을 점수에서 빼면 이 문제도 같이 사라진다.
- 방향성 편향: `narrative_depth`(학생 −0.9), `exploration_reward`, `build_variety`, `endgame_content`
  는 같은 게임에서 학생이 1점 안팎 낮게 준다. 거리 계산에 들어가면 학생 코호트가 "서사" 계열
  질의에서 조금 불리하다. 크지 않지만 **코호트를 한 풀에 섞어 정렬하는 한 남는 편향**이다.

판정: **"교사와 차이 없어야 한다"는 기준은 취향 매칭 용도로는 충족. 임계값 용도로는 미충족.**
후자를 쓰는 곳(X-Factor)을 없애면 기준 전체가 충족된다.

**바뀐 순서와 이유:**

1. **교사 리뷰 백필을 지금 바로 백그라운드로** (`refresh_reviews --cohort teacher --new`, 무료 1.2h).
   순서에 놓을 이유가 없다. gem 전환·유명작 필터·D-4 전부가 이걸 기다린다.
2. **`--save s1_after_gate`** (캐시 차단 적용된 첫 스냅샷). 지금 상태의 기준선.
3. **Day 1 폴백 수정 커밋 — 작게.** D-10 `or 5.0`→`resolve_null`, D-2 `or 50`→`is None`(4곳 +
   포맷터 3곳의 `gem_percentile or gem_potential`), D-24, D-22, nullslast, 시맨틱 하한 0,
   캐시 키 조건 + `CACHE_VERSION`, **포맷터 B/C 에 `score_breakdown` 추가**(관측 가능하게).
   D-16(`[:20]`)은 프롬프트 변경이라 문장 검색 결과가 통째로 바뀐다 — 별도 커밋.
   → `--save s2` → `--diff s1 s2`. **D-10 하나로 공포·힐링 시나리오가 크게 바뀌는 게 정상.**
4. **Core 재설계를 gem 전환보다 앞에 둔다.** 75점 항의 구조 결함(D-26·D-8 일반화) > 6점 항의 입력 교체.
   결정할 것(개발자 판단, 아래 §6 권고):
   - 장르 핵심 목표 5.0 을 **없앤다** (사용자가 말하지 않은 지표를 목표로 삼지 않는다)
   - `v >= 7` 임계를 **없앤다** — 사용자가 준 값은 전부 목표다. 9 도 1 도.
   - 가중치: 사용자 지정 지표만 거리에 넣는 **질의 마스크** + 가중 RMSE `sqrt(Σw·diff²/Σw)`
     (D-20 의 w² 문제도 이걸로 같이 해결)
   - X-Factor 제거(또는 질의 방향에 맞는 지표만 남긴 소형 항). 같은 변경 창.
   - 저차원 동점 문제는 임베딩 코사인을 작은 비중의 타이브레이커로 넣어 해소
     (경로 B 가 이미 40% 로 쓰고 있다 — 경로 A 만 임베딩을 안 쓴다)
   → 이 변경은 **순위가 크게 바뀌는 것이 정상**이다. "상위 10 절반 유지" 기준 적용 금지.
5. **절제(ablation) 도구를 이 단계 전에 만든다.** 스냅샷은 상위 10 만 담아 순위 영향력을
   못 잰다. batch 컨테이너에서 활성 풀 전체를 `score_v6` 함수로 채점하고 항을 하나씩 끄며
   Kendall τ / RBO 를 내는 스크립트 — 비용 0, 반나절. **이게 있어야 4번의 전후를 말할 수 있다.**
   부수 효과로 "X-Factor 15.6 미만이 전체 풀의 몇 %인가"(§3-b)가 바로 나온다.
6. gem 전환 (교사 리뷰 백필 완료 후): 컬럼 분리(`gem_evidence_score` + status, NULL≠0),
   `gem_potential` 폴백·`review_bonus`·`discovery+quality`·`× confidence` 제거, 뱃지 임계 재조정(D-13).
7. `--threshold-report` 로 노출 임계값 확정 → 게이트 재적용.
8. 백필 재개($27) — 점수 로직과 독립이므로 비용 승인만 있으면 아무 때나. 단 동시 실행 금지(C-7).
9. `git push`.

## 6. Core 재설계 권고안 (결정은 개발자가)

의도 확정: "점수는 사용자의 취향/검색문장에 따라 달라진다." 이 의도를 가장 직접 구현하는 형태:

```
지정 지표 집합 P = preferences.keys()               # 임계 없음. 0 도 9 도 목표.
w_f = 1 + |pref_f − 5| / 5                          # 극단 선호는 더 세게 (1.0 ~ 2.0)
dist = sqrt( Σ_{f∈P} w_f · (pref_f − game_f)² / Σ w_f )   # 가중 RMSE, 0~10 스케일
match = sigmoid(dist)                                 # 거리 0 → 1.0 이 되게 재정규화 (D-7 해결)
core  = match × 75
tie   = 임베딩 코사인(질의 텍스트 또는 프리셋 설명문 vs 게임) × 소형 예산   # 동점 해소
gem   = 증거 지수 (전환 후)                              # 6점, 리뷰 근거 없으면 0 (NULL 은 미노출)
```

- 장르 핵심 지표는 **점수에서 빠진다.** "장르 정체성"이 필요하면 설명(match_reason)에만 쓴다.
- 폴백은 `resolve_null` 정책 그대로(D-10 해결). 사용자가 말하지 않은 지표는 **거리에 안 들어간다.**
- `must_not` 은 안전망이 아니라는 판정 유지 — 질의 마스크 위에 방향성 역지표 소프트 페널티
  또는 must_not 자동 유도 중 하나를 같이 넣는다.
- 경로 B/C 는 그대로 두고 **표시 척도만 통일**(D-11): 세 경로가 같은 0~99 를 쓰려면 raw 정규화 재조정.

이 안의 위험: 사용자가 지표 1개만 주면 거리가 1차원이라 동점이 많다 → tie 항이 필수.
그래도 지금의 "말하지 않은 5개가 말한 1개를 이기는" 구조보다 의도에 가깝다.

## 7. 노출 임계값 판정

2단 권고(노출 `리뷰 ≥ 3 AND Wilson ≥ 0.35`, 뱃지 `리뷰 ≥ 30`)는 타당하다.
Wilson 0.35 는 n=3 이면 3/3, n=6 이면 5/6 이상을 뜻한다 — "최소한의 긍정 증거"로 읽힌다.
개수만 쓰면 양방향 오류(10@60% 통과 / 3@100% 탈락)가 실재한다.
**단, 이 결정은 점수 문제와 독립이다.** `--threshold-report` 실측 후 결정하면 되고, 지금 서두를 이유 없다.
"가능성 보존" 취지와도 맞다 — 데이터는 남고 노출만 조절한다.
