# 셀프 피드백 — v7 결정을 PRD·실제 사용 동선에 대고 다시 봄 (2026-09-05)

개발자 지시: "PRD 에 점수 매기는 방식 있다. 목표는 사용자 취향에 맞는 게임 찾기 — 검색 문장/단어/문단,
또는 취향 분석. 그래서 지표를 세분화했다(원래 13개 → 49+9). 고치기 전에도 어느 정도 잘 됐다. 방향은 맞다."

이걸 기준으로 어제·오늘 내 결정을 다시 검토했다. **결론: v7 의 핵심(말한 지표만, 말한 값 그대로)은
유지. 그러나 세 가지를 내가 과하게 잘랐거나 놓쳤다.**

---

## 1. PRD 가 말하는 점수 — 코드와 대조

PRD §4 "추천 엔진 v5" (`PRD_v4.2.3.md:210-253`):
```
지표 유사도 (60%) = 가중 유클리드(67%) + 코사인(33%)
임베딩 (40%)      = pgvector 코사인
→ 0~94 + gem 최대 +5 = 0~99
4단계 가중치 5.0 / 2.0 / 0.5 / 0.1   "변별력: 25 vs 3.5 → 7배"
의도 그룹 12개 → Macro Vibe 12개 추가 → 24개
```

대조 결과:
- **PRD 의 엔진은 경로 B(유사 게임)의 공식이다.** 경로 A 의 v6(Core 75 + X-Factor 18 + Gem 6)는
  PRD 어디에도 없다. v6 는 PRD 이후 붙은 층이다. → v7 이 v6 를 대체하는 것은 PRD 를 어기는 게 아니다.
- **PRD 의 "49개 전부 비교"는 기준이 게임일 때 성립한다.** 기준 게임은 49차원이 다 차 있다.
  취향 입력(3~5개 지표)에서는 나머지 45개의 목표값이 없다 — v6 가 5.0 으로 메운 것이 D-26 이었다.
  즉 PRD 의 4단계 가중치 자체는 옳고, **취향 경로에 그대로 옮긴 것이 틀렸다.**
- "변별력 25 vs 3.5" — 25 = 5.0². **PRD 는 가중치가 제곱되는 것을 알고 썼다.** 어제 D-20("w² 는 버그")은
  경로 B 에 대해서는 **의도된 동작**으로 봐야 한다. 경로 B 의 거리 공식은 건드리지 않는다. (정정)
- 세분화의 의미: 13개일 때는 "액션인가"만 알았고, 49개면 "손맛 액션인데 시간 압박은 낮고 고어는 없다"를
  안다. **세분화의 가치는 사용자가 그 축을 지정할 수 있다는 데 있다** — v7 의 마스크는 그 축을 그대로 쓴다.
  세분화의 가치를 살리는 건 "49개 전부를 항상 비교"가 아니라 "사용자가 말한 축을 정확히 비교"다.

## 3. 내가 과하게 잘랐거나 놓친 것

### 3-a. "취향 없음" 입력의 정의가 없다 (놓침, 치명)
슬라이더를 안 움직이면 프런트가 49개 전부 5.0 을 보낸다. v6 도 v7 도 "모든 축에서 5 인 게임"에 만점을 준다.
이건 "취향 없음"이 아니라 "모든 축에서 평범함을 원함"으로 읽힌 것이다.
→ **결정 추가 R-8**: 백엔드가 `|v−5| < 0.5` 인 지표를 preferences 에서 제거한다. 남는 게 없으면
  "발견 모드" — Core 없이 gem(증거) → Wilson → 무명 순으로 정렬해 돌려준다. 프런트 폴백도 `{}` 로 바꾼다.
  (`recommender.py` 진입부 한 곳 + `page.tsx:157`)

### 3-b. Vibe 칩 2~3개 지표 → 동점 수백 개 (과하게 잘랐음, 높음)
v6 는 X-Factor 와 장르 핵심 덕에 동점이 거의 없었다 — 틀린 이유로 갈랐지만 갈랐다.
v7 은 2차원이면 정확히 같은 값의 게임이 수백 개다. 그 뒤는 gem(6점) 이 결정하는데 gem 은 리뷰 없으면 0 이다.
"어느 정도 잘 됐다"의 일부는 X-Factor 가 **풍부한 게임을 위로 올린 효과**였을 가능성이 있다. 그걸 대체 없이 뺐다.
→ **결정 수정 R-1'**: 두 갈래.
  (1) **의도 그룹의 secondary 지표를 목표값과 함께 정의**해 Vibe 칩에 붙인다. PRD §4-3 의 의도 그룹이
      바로 이 용도다(primary 3~5 + secondary 5~8). 지금 `INTENT_TO_METRIC_GROUPS` 는 지표 이름만 있고
      **방향(목표값)이 없다** — 그래서 v6 가 못 썼다. 각 Vibe 에 secondary 5~8개를 `지표: 목표값` 으로 적고
      가중치 0.5 로 마스크에 넣는다. 사용자가 안 말한 축이지만 **Vibe 정의가 말한 축**이므로 D-26 과 다르다.
      → `vibe_config.py` 의 각 Vibe 에 `secondary: {...}` 추가. 12개 × 6개 = 72개 숫자, 개발자가 정한다.
  (2) gem 예산을 v7 에서 6 → **12** 로 올린다 (Core 87 + gem 12). 동점을 실제 리뷰 증거로 갈라야 한다면
      6점은 너무 작다. 단 gem 전환(R-3) 이후에만 — 지금 gem 입력(LLM percentile)로 12점을 주면 r=−0.022 짜리
      신호가 커진다. **전환 전까지는 6 유지.**
  둘 다 한다. (1)이 본질, (2)가 보조.

### 3-c. τ = 3.5 의 강도 (재검토, 중간)
두 지표 중 하나가 8점 어긋나면 93 → 6.8. "낮은 시간 압박 원함"에 시간 압박 9 게임이면 맞다.
그러나 4개 지표 중 하나가 3점 어긋나면 dist ≈ 1.6 → 0.81 → 75. 3점 차이로 18점을 잃는다.
슬라이더 값은 사용자가 정확히 정한 게 아니라 대략이다(5 → 7 로 밀었을 뿐). 3점 차이에 18점은 과하다.
→ **τ 는 절제 실측 후 3.5 ~ 5.0 사이에서 정한다.** 판정 기준: 프리셋 상위 20 의 Core 폭이 10~25점 사이
  (지금 v6 는 5.7 로 너무 좁고, τ=3.5 는 60+ 로 너무 넓을 수 있다). 지금은 결정 보류, 상수만 노출.

### 3-d. 경로 B 의 D-20·D-12 는 건드리지 않는다 (정정)
§1 에서 확인 — PRD 가 제곱 강조를 알고 썼다. 어제 "높음"으로 올린 D-20 을 **경로 B 에 대해서는 기각**한다.
v7(경로 A)은 가중치 1~2 라 제곱해도 4배가 최대여서 어느 쪽이든 문제 없다.

### 3-e. 내가 유지하는 것
- 장르 핵심 목표 5.0 제거 — 이건 어떤 관점에서도 결함이다. 유지.
- `v >= 7` 임계 제거 — 힐링 프리셋 4개 중 3개가 버려지던 것. 유지.
- X-Factor 제거 — 질의 정보 0. 단 3-b 의 대체(secondary + gem 증거)를 같은 변경 창에 넣는다.
- 캐시 오염 차단, 0≠NULL 수정, 포맷터 breakdown — 유지.

## 4. "고치기 전에도 잘 됐다"에 대한 내 해석

s0 상위 10 을 보면 힐링→코지 게임, 전략→전략 게임, 공포→공포 게임이 나온다. **방향은 맞았다.**
이유: 의도 지표(가중치 2.0)가 장르 핵심(5.0 목표, 가중치 1.0)보다 세서 큰 방향은 잡혔다.
틀린 곳은 **그 방향 안에서의 순서**다 — 코지 게임들 중 평범한 것이 뛰어난 것 위에 왔다(D-26),
그리고 사용자가 "낮게" 원한 축은 무시됐다(v>=7). 즉 "잘 됐다"는 관찰과 "결함이 있다"는 진단은 양립한다.
v7 은 방향을 바꾸는 게 아니라 **같은 방향 안에서 순서를 사용자의 말대로 고치는 것**이어야 하고,
그래서 절제 실측의 합격 기준은 "상위권이 전부 바뀐다"가 아니라 **"프리셋의 장르 방향은 유지되면서
상위권 안의 순서와 구성이 바뀐다"** 다. 어제 "대폭 변화가 정상"이라고 쓴 건 과했다 — 정정.

## 5. 결정 기록 수정 사항 (decisions_0905.md 에 반영)
- R-1' : Vibe secondary 목표값(가중 0.5) 추가, gem 예산 12 는 gem 전환 후, τ 는 실측 후 3.5~5.0
- R-8  : "취향 없음" 정의 — 중립값 제거, 비었으면 발견 모드
- D-20 : 경로 B 에서는 의도된 동작(PRD §4-2). 기각.
- 절제 합격 기준: 장르 방향 유지 + 상위권 순서·구성 변화. "대폭 변화가 정상" 철회.
