# Hidden Gem — 제품 개요 (한 장)

상세 PRD(로드맵·사업 모델·요금 설계)는 비공개다. 이 문서는 **무엇을 문제로 봤고, 무엇을 만들지 않았는지**를
한 장에 적은 것이다. 기술 구현은 [README](../README.md), 결정 이력은 [decisions](./decisions_0905.md)를 본다.

---

## 1. 문제

스팀에는 매년 1만 개 이상이 출시되는데, 발견 경로는 두 개뿐이다 — **인기 순위**와 **장르 태그**.

- 인기 순위는 이미 팔린 게임을 다시 보여준다. 리뷰 100개짜리 좋은 게임은 구조적으로 노출되지 않는다.
- 장르 태그는 "이 게임이 **왜** 좋았는지"를 설명하지 못한다. `로그라이크`·`인디` 두 태그를 공유하는 두 게임이
  전혀 다른 경험일 수 있다. 사용자가 실제로 원하는 것은 "혼자 조용히, 전략적으로, 스트레스 없이" 쪽이다.
- 그래서 사람들은 커뮤니티에 **문장으로** 묻는다. "이런 거 또 없나요?" 이 질문에 답하는 서비스가 없다.

## 2. 가설

게임을 **경험 단위의 지표**로 분해하면, 취향을 문장이나 값으로 입력해 찾을 수 있다.

- 지표는 장르가 아니라 경험이다 — 아늑함, 전략 깊이, 손맛, RNG 의존도, 관리 복잡도, 서사 깊이, 리플레이…
- 게임당 60개(수치 49 + 불리언 태그 9 + 신뢰도). 7개 그룹으로 접어 두고 원하는 축만 조정한다.
- 검증 방식: 사용자가 조정한 축만으로 순위가 결정되는지, 그리고 그 순위가 **교사 모델이 아는 인기작 쪽으로
  쏠리지 않는지**를 절제 실험으로 측정한다 ([ablation](./ablation_result_0905.md)).

## 3. 타깃 (1년차)

| 대상 | 이 사람이 지금 겪는 일 |
|---|---|
| 취향이 뚜렷한 게이머 | 원하는 조건을 아는데 검색으로 표현할 방법이 없다 |
| "이런 거 또 없나" 캐주얼 | 방금 재밌게 한 게임과 비슷한 걸 커뮤니티에 물어본다 |
| 인디 게임 팬 | 좋은 인디가 리뷰 수 때문에 안 보인다 |

1년차는 한국 사용자만 본다. 글로벌·B2B는 이 검증 다음이다.

## 4. 제품 원칙 — 다섯 개

**① 근거가 없으면 점수를 주지 않는다.**
발굴 지수는 LLM 추정이 아니라 리뷰 실측(Wilson 하한 × 무명도)이다. 리뷰가 부족하면 `NULL` 로 두고
중앙값 같은 폴백을 넣지 않는다. 폴백은 "모르는 것"을 "보통"으로 바꿔 순위에 개입한다.

**② 신작·정착·유명 게임을 같은 척도에 올리지 않는다.**
취향 일치는 같은 척도로 재도 되지만, 발굴은 아니다. 출시 180일 이내 게임을 정착작과 발굴로 경쟁시키면
데이터가 적은 쪽이 항상 이기거나 항상 진다. 그래서 신작은 별도 보드·별도 섹션으로 뺐다.

**③ 사용자가 건드리지 않은 축은 순위에 개입하지 않는다.**
슬라이더를 만지지 않은 지표는 가중치 0(질의 마스크)이다. 기본값 5.0 을 "보통을 원한다"로 읽으면
말하지 않은 요구가 순위를 흔든다. 실제로 그 버그가 있었고, 절제로 발견했다.

**④ 화면에는 내부 용어를 쓰지 않는다.**
`정착 게임`·`인지도 대비 평가`·`그들만의 리그` 가 그대로 화면에 나가 있었다 → `숨은 명작`·`요즘 뜨는`·`신작`.
설계 언어와 사용자 언어를 분리하지 않으면, 만든 사람만 이해하는 화면이 된다.

**⑤ 약점을 화면에서 감추지 않는다.**
데이터가 아직 없는 보드는 "데이터 축적 중"이라고 쓴다. 리뷰가 적은 신작을 추천할 때는
"분석 정확도가 낮을 수 있다"를 같이 보여준다. 숨은 명작 1위가 리뷰 82건인 것도 README에 적어 뒀다.

## 5. 무엇을 재는가

행동 로그(`UserAction`)와 운영 대시보드(`/admin/dashboard/`)에 실제로 붙어 있는 것만 적는다.

| 질문 | 측정 |
|---|---|
| 추천이 실제로 클릭되나 | 상세 조회 → 스팀 이동 전환율 (`detail_view` → `steam_click`) |
| 취향 입력이 부담스럽지 않나 | 취향 분석 진입 → 결과 요청 도달률, 카드 스와이프 대안 선택 비율 |
| 다시 오나 | 세션 기준 일·월 방문, 같은 게임 재방문(`revisit`) |
| 취향을 남길 만큼 믿나 | 로그인 후 취향 저장 비율, 회원가입 넛지 전환 |
| 발굴이 실제로 발굴인가 | 추천 결과의 리뷰 수 중앙값·교사 모델 인기작 비율 (절제 스냅샷) |

마지막 줄이 이 제품의 핵심 지표다. **추천 결과가 유명작으로 쏠리면, 기능이 다 돌아도 제품은 실패한 것이다.**

## 6. 만들지 않은 것 — 그리고 이유

| 안 만든 것 | 이유 |
|---|---|
| 협업 필터링 | 신규 서비스에 행동 데이터가 없다. 인디 롱테일은 데이터가 쌓여도 희소하다. 로그 인프라는 먼저 깔아 뒀다 |
| 신작에 중립 발굴 점수 부여 | 원칙 ①을 깬다. "모른다"를 "보통"으로 바꾸는 일 |
| 비속어 필터 | 검색어가 다른 사용자에게 노출되는 경로가 없다. 막을 대상이 없는 방어는 넣지 않는다 |
| 메인 상단의 신작 포함 토글 | 켜도 결과가 거의 안 바뀌었다(절제로 확인). 토글이 아니라 별도 섹션이 맞았다 |
| 개인화 레이어 | 데이터 수집 인프라는 출시 전에, 분석 로직은 데이터가 쌓인 뒤에 |
| B2B 기능 | B2C 검증 전에 만들면 검증할 대상이 흐려진다 |

## 7. 지금 진행 중 / 아직 안 되는 것

- **`요즘 뜨는` 보드가 비어 있다.** 리뷰 이력 행은 17,556개인데 같은 게임의 **두 시점** 스냅샷이 없어
  30일 증가량이 계산되지 않는다. 주간 실행이 쌓이면 4~5주 뒤 자동으로 채워진다. 그동안은 "데이터 축적 중" 표기.
- **숨은 명작 1위가 리뷰 82건이다.** 리뷰 하한 30이 낮아 정렬이 "가장 무명한 것이 이긴다"에 가깝다.
  하한 100/300/500 절제 비교 대기 중 — 예측을 먼저 적고 측정한다.
- **Vibe Cluster**(경험 묶음 12개 → 자연 진화) 설계만 끝났고 미구현.
