# project_way.md

# AI 기반 개인화 게임 추천 웹 서비스 - 개발 진행 가이드

## 0. 이 문서의 목적

이 문서는 프로젝트를 처음부터 끝까지 만들기 위한 **개발 방향 문서**이다.

나는 아직 웹, 백엔드, DB, 추천 시스템, AI 기능에 대한 지식이 충분하지 않기 때문에  
처음부터 완성된 서비스를 한 번에 만들지 않고,  
**기초 → 구조 → 기능 → 추천 → AI** 순서로 천천히 확장한다.

즉, 이 문서는

- 지금 당장 무엇을 해야 하는지
- 왜 이걸 먼저 해야 하는지
- 어떤 파일을 만들지
- 어떤 수준까지 구현할지

를 정리한 **프로젝트용 로드맵**이다.

---

# 1. 프로젝트 최종 목표

이 프로젝트의 최종 목표는

**사용자 취향과 게임 메타데이터를 기반으로,  
숨은 선호 게임을 설명 가능하게 추천하는 AI 기반 개인화 웹 서비스**를 만드는 것이다.

단, 처음부터 AI까지 모두 붙이지 않는다.

먼저 아래 순서대로 진행한다.

1. DB 설계
2. 추천 로직 (rule-based)
3. FastAPI 기본 API
4. 프론트 연결
5. AI 기능 추가

---

# 2. 전체 개발 단계

## STEP 1. DB 설계
### 목표
- 어떤 데이터를 저장할지 정한다.
- 추천 기능에 필요한 최소 데이터 구조를 만든다.

### 왜 먼저 해야 하는가?
추천도, API도, 프론트도 결국 데이터를 기반으로 움직인다.  
DB 구조가 없으면 나중에 전체를 다시 뜯어고쳐야 한다.

### 이 단계에서 할 일
- 게임 테이블 설계
- 사용자 테이블 설계
- 사용자 선호 테이블 설계
- 추천 결과 / 피드백 저장 구조 생각하기

### 결과물
- `docs/db_design.md`
- `backend/app/models/` 안의 모델 파일들

### 지금 필요한 공부
- DB란 무엇인가
- 테이블 / 컬럼 / PK / FK
- 관계형 데이터베이스 기초
- PostgreSQL 기초
- ORM 기초 (SQLAlchemy)

---

## STEP 2. 추천 로직 (rule-based 먼저)
### 목표
- AI 없이도 작동하는 추천 기능을 먼저 만든다.

### 왜 먼저 해야 하는가?
처음부터 AI 추천으로 가면 구조를 이해하기 어렵고 디버깅도 힘들다.  
먼저 규칙 기반 추천을 만들면 추천 시스템의 흐름을 이해할 수 있다.

### 1차 추천 방식
- 사용자가 좋아한 장르와 같은 게임 추천
- 사용자가 선호한 태그가 많은 게임 추천
- 사용자가 싫어하는 요소는 감점

### 예시
- 액션 + 탐험을 좋아하면 해당 점수를 높임
- 공포를 싫어하면 공포 태그 있는 게임 감점

### 결과물
- `recommendation/rule_based.py`
- `recommendation/scoring.py`
- `docs/recommendation_logic.md`

### 지금 필요한 공부
- 점수화 방식
- 딕셔너리 활용
- 리스트 순회
- 정렬 (`sorted`)
- 간단한 함수 분리

---

## STEP 3. FastAPI 기본 API
### 목표
- 백엔드 서버를 만들고 데이터를 주고받을 수 있게 한다.

### 왜 필요한가?
프론트엔드는 직접 DB와 대화하지 않는다.  
중간에서 데이터를 전달하는 API 서버가 필요하다.

### 이 단계에서 만들 기능
- 게임 목록 조회 API
- 게임 상세 조회 API
- 사용자 선호 저장 API
- 추천 결과 반환 API

### 결과물
- `backend/app/main.py`
- `backend/app/api/game.py`
- `backend/app/api/user.py`
- `backend/app/api/recommendation.py`

### 지금 필요한 공부
- API란 무엇인가
- GET / POST 차이
- FastAPI 기본 문법
- Pydantic schema 기초

---

## STEP 4. 프론트 연결
### 목표
- 사용자가 실제로 보는 화면을 만들고 백엔드와 연결한다.

### 이 단계에서 만들 화면
- 메인 화면
- 취향 입력 화면
- 추천 결과 화면
- 게임 상세 화면

### 핵심
이 단계에서는 디자인보다 **흐름 연결**이 중요하다.

예:
- 사용자가 게임 선택
- 선택값이 백엔드로 전달
- 추천 결과를 받아서 화면에 출력

### 결과물
- `frontend/app/`
- `frontend/components/`
- `frontend/services/`

### 지금 필요한 공부
- React / Next.js 기초
- 컴포넌트 개념
- 상태(state)
- fetch / axios로 API 호출
- props 기초

---

## STEP 5. AI 기능 추가
### 목표
- 추천 이유 설명
- 임베딩 기반 유사도 추천

### 왜 마지막인가?
AI 기능은 가장 나중에 붙여도 된다.  
기본 서비스가 먼저 동작해야 AI를 붙였을 때 어디가 문제인지 알 수 있다.

### AI 1차 적용
- 추천 결과에 설명 문장 생성
- 사용자가 왜 이 게임을 좋아할지 설명

### AI 2차 적용
- 게임 설명/태그를 임베딩으로 변환
- 사용자 취향 벡터와 유사한 게임 찾기

### 결과물
- `backend/app/services/embedding_service.py`
- `backend/app/services/llm_service.py`
- `embeddings/generate_embeddings.py`

### 지금 필요한 공부
- 임베딩이 무엇인지
- 벡터 유사도가 무엇인지
- LLM은 어디에 써야 비용이 적은지
- API 호출 구조 이해

# 7. 내가 이 프로젝트를 하면서 잊지 말아야 할 것

## 1. 처음부터 완벽하게 만들려고 하지 말 것
이 프로젝트는 공부하면서 만드는 프로젝트다.  
처음부터 큰 구조를 전부 완성하려고 하면 멈추게 된다.

## 2. AI는 마지막에 붙인다
AI가 핵심 차별점은 맞지만,  
서비스 구조와 추천 흐름을 이해한 뒤 붙여야 한다.

## 3. 먼저 "동작하는 작은 것"을 만든다
큰 기능 하나보다,
작게라도 실제로 돌아가는 기능 하나가 더 중요하다.

예:
- 게임 10개 데이터로 추천 1개 나오기
- 사용자 취향 입력값 저장하기
- 추천 결과 3개 출력하기

## 4. 문서도 프로젝트의 일부다
이 프로젝트는 취업용 포트폴리오이기도 하므로  
README, DB 문서, 아키텍처 문서도 중요한 결과물이다.
